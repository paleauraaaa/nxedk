# nxedk - the new xenon development kit.

nxedk (stylized all-lowercase) is an experimental FOSS SDK targeting the
Xbox 360. It includes a custom LLVM toolchain and rustc for codegen and 
linking, import libraries to access the kernel and XAM, a libc and allocator,
an XEX packer, and other libraries.

Interfacing with existing code generated by Microsoft's XDK is *possible*, as
it was required to make syscalls, but it is unsupported. No Microsoft code is 
included in this repository or the toolchain.

## Prerequisites

- Git. Of course.
- Python 3 with pip.
- CMake 3.20 or newer.
- Meson installed for that Python: `python -m pip install meson`.
- Ninja (recommended)

## Build

First, clone the repo and build the libraries.
```bash
$   git clone -c core.symlinks=true --recurse-submodules https://github.com/paleauraaaa/nxedk.git
$   cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
$   cmake --build build
```

This builds libnxedk, xboxkrnl.lib, xam.lib, libc, crt0, and mimalloc. 

To compile an executable, a pre-built, minimal clang/LLVM toolchain is shipped 
at `toolchain/<platform>/bin/llvm`. In the alternative, the full toolchain can 
be downloaded and compiled from source at 
https://github.com/paleauraaaa/llvm-project (xbox360 branch).

Pass `--target=powerpc64-unknown-xbox360` for the target triple and compile
as usual.

To link an executable, any of the linker flavors will work. Make sure to link
with the libraries built above. See `examples/exit`.

The Xbox 360's kernel and XAM APIs are provided through xboxkrnl.lib/xboxkrnl.h
and xam.lib/xam.h. picolibc provides a partial POSIX implementation and C 
stdlib. libnxedk provides its own additional APIs.

DO NOT use a system-provided clang/LLVM. Xbox 360 support involved significant
modifications that HAVE NOT been upstreamed.

## Rust

`no_std` Rust crates can be compiled with a modified Rust toolchain. Clone it
from https://github.com/paleauraaaa/rust (xbox360 branch), build the stage0
and stage1 compiler/libraries as normal, then use `rustup toolchain link` to 
access the toolchain anywhere.

When building an Xbox 360 crate, make sure to use the Xbox 360 toolchain
(e.g., `cargo +xbox360 build` for a toolchain named `xbox360`, 
instead of just `cargo build`) and the Xbox 360 target 
(`--target=powerpc64-microsoft-xbox360`). Xbox 360 builds require some 
additional environment variables and build logic. See `.cargo/config.toml`
and `build.rs` in `examples/rust`.

`cargo build` will invoke the Xbox 360 linker with the necessary system
libraries, so unlike with a C executable, no additional linking step will be
necessary.

The `xbox360-env` crate sets up a basic `no_std` environment, including the 
global allocator. See its README for more details.

## XEX

To actually run an executable (either on real hardware or an emulator), the
executable will need to be converted to an XEX. Use the provided SynthXEX tool
(or https://github.com/paleauraaaa/SynthXEX to build from source) for this.

## Debugging

LLDB can be attached to the xenia-canary fork at 
https://github.com/paleauraaaa/xenia-canary (nxedk branch), and lldb-dap will
facilitate interactive debugging in an IDE. 

Debugging on real hardware is currently unsupported, but is intended to be 
added in the future.
